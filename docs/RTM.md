# Matriz de trazabilidad de requisitos

Las historias de usuario de esta matriz se infirieron de las funcionalidades y pruebas ya presentes en el repositorio, ya que no se suministró un backlog externo. Los identificadores `US-*` son provisionales: deben sustituirse por los IDs oficiales del curso o del proyecto si existen.

| ID / historia de usuario | Criterio de aceptación asociado | Implementación | Prueba de calidad asociada |
| --- | --- | --- | --- |
| US-01 — Como usuario registrado, quiero iniciar sesión y acceder solo a las operaciones permitidas por mi rol. | Credenciales válidas entregan un JWT; las inválidas se rechazan; una ruta protegida rechaza solicitudes sin token y las operaciones restringidas validan el rol. | `POST /api/v1/auth/login`, `GET /api/v1/auth/perfil`; `src/services/authService.js`; `src/middlewares/auth.js`. | `tests/auth.test.js`: `test_login_exitoso`, `test_login_credenciales_invalidas`, `test_ruta_protegida_sin_token`; `tests/tickets.test.js`: `test_admin_no_vende`. |
| US-02 — Como vendedor, quiero vender apuestas de Chance válidas y consultar el premio tras el sorteo. | Se aceptan apuestas válidas; se rechazan números, modalidades o valores inválidos; el premio se calcula sobre las últimas cifras del resultado. | `POST /api/v1/tickets/chance`; `src/services/ticketService.js`; `src/services/chanceService.js`; liquidación en `src/services/sorteoService.js`. | `tests/tickets.test.js`: `test_venta_chance`, `test_resultado_y_pago_premio`; `tests/chance.test.js`: `test_premio_directo_4_cifras`, `test_premio_directo_ultimas_cifras`, `test_premio_combinado_divide_por_permutaciones`, `test_validacion_apuesta_invalida`. |
| US-03 — Como vendedor, quiero vender jugadas de Baloto manuales o aleatorias. | El tiquete acepta jugadas válidas y aleatorias, cobra por jugada y rechaza números repetidos o fuera de rango. | `POST /api/v1/tickets/baloto`; `src/services/ticketService.js`; `src/services/balotoService.js`. | `tests/tickets.test.js`: `test_venta_baloto`; `tests/baloto.test.js`: `test_jugada_aleatoria_valida`, `test_jugada_numeros_repetidos`, `test_premio_por_aciertos`. |
| US-04 — Como administrador, quiero crear sorteos y registrar sus resultados para liquidar los tiquetes activos. | Un administrador crea sorteos futuros; al registrar un resultado válido el sorteo pasa a jugado y los tiquetes se liquidan; no se permite repetir el resultado. | `POST /api/v1/sorteos`, `POST /api/v1/sorteos/{id}/resultado`; `src/services/sorteoService.js`. | `tests/caja.test.js`: `test_admin_crea_sorteo`; `tests/tickets.test.js`: `test_resultado_y_pago_premio`. |
| US-05 — Como usuario autenticado, quiero consultar tiquetes y anular una venta elegible con una justificación. | Un vendedor solo anula sus tiquetes, dentro del plazo y antes del sorteo; se exige motivo y no se anulan tiquetes de otro vendedor. | `GET /api/v1/tickets`, `GET /api/v1/tickets/{codigo}`, `POST /api/v1/tickets/{codigo}/anular`; `src/services/ticketService.js`. | `tests/tickets.test.js`: `test_anulacion_ticket`, `test_anulacion_fuera_de_tiempo`. |
| US-06 — Como vendedor, quiero revisar y cerrar mi caja diaria con la diferencia entre efectivo y saldo esperado. | El resumen consolida ventas y premios; el cierre registra faltantes/sobrantes y no admite un segundo cierre diario. | `GET /api/v1/caja/resumen`, `POST /api/v1/caja/cierre`; `src/services/cajaService.js`. | `tests/caja.test.js`: `test_resumen_caja_diario`, `test_cierre_caja_con_faltante`. |

## Observaciones de cobertura

- La matriz enlaza los criterios con las pruebas automatizadas existentes; no representa pruebas manuales independientes.
- La consulta de perfil, listados y detalle de sorteos, filtros de tiquetes, pago de premios caducados y algunos errores de cierre no tienen pruebas específicas identificadas en el conjunto actual. Conviene incorporarlas si forman parte de los criterios oficiales de evaluación.
- Las rutas, permisos, cuerpos de solicitud y respuestas documentados se pueden explorar en [Swagger UI](http://localhost:3000/api-docs) cuando el servidor esté activo.
